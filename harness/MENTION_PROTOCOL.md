# @Ryan Mention Protocol

## Core Principle

Ryan의 시간은 소중합니다. 에이전트끼리 해결할 수 있는 건 해결하고,
정말 사람의 판단이 필요한 경우에만 멘션합니다.

## 멘션 채널

| 우선순위 | 채널 | 용도 |
|---------|------|------|
| 긴급 | Telegram DM + Discord #alerts | 보안, 프로덕션 장애 |
| 높음 | Discord #control / Telegram | 3회 실패, 설계 결정 |
| 일반 | Discord #control / Telegram | 작업 완료 승인 요청 |
| 낮음 | Discord #session-log | 리소스 경고, 일일 리포트 |

## 멘션 트리거

### 반드시 멘션

1. **작업 100% 완료 + 모든 eval 통과**
   ```
   ✅ 완료: [태스크 이름]
   - Scores: F:8 / CQ:7 / S:9
   - Iterations: 2/3
   - Branch: feat/xxx
   - 승인 요청합니다.
   ```

2. **3회 반복 후에도 eval 미달**
   ```
   ⚠️ 개입 필요: [태스크 이름]
   - 지속 실패 기준: Security 5/7
   - 시도한 수정 요약: [1줄씩]
   - 제 판단으로는 [의견]이지만 결정 부탁드립니다.
   ```

3. **보안 이슈 (즉시, 반복 없이)**
   ```
   🚨 긴급 보안: [설명]
   - 발견 위치: [파일:라인]
   - 위험도: critical/high
   - 임시 조치: [했으면 설명 / 안 했으면 "대기 중"]
   ```

4. **아키텍처/설계 결정 필요**
   ```
   ❓ 결정 필요: [주제]
   - Option A: [설명] — 장점/단점
   - Option B: [설명] — 장점/단점
   - 제 추천: [A or B], 이유: [1문장]
   ```

### 멘션하지 않는 상황

- eval 1~2회차 실패 → 에이전트끼리 해결
- 린트/타입 에러 → 자동 수정
- 테스트 실패 → 자동 디버깅 + 수정
- 커밋 메시지 포맷 오류 → 자동 수정
- 문서 불일치 → GC에서 자동 PR
- Codex 일시적 API 오류 → 재시도

### 판단이 필요한 경계 상황

- 에이전트 간 의견 충돌 2회 연속 → 멘션
- 리소스 일일 한도 80% 도달 → 멘션 (낮음 우선순위)
- 새로운 유형의 실패 패턴 발견 → 멘션 (하네스 개선 제안)

## 메시지 포맷 규칙

1. **1줄 요약 먼저** — 스크롤 없이 핵심 파악
2. **점수는 축약** — F:8/CQ:7/S:9 (풀네임 불필요)
3. **액션 명확히** — "승인 요청", "결정 필요", "확인 필요"
4. **컨텍스트 최소화** — 필요한 정보만, 장황하게 설명 X
5. **한국어 사용** — Ryan은 한국어가 편함
